# daport 6단계 설계 스펙: AI 이미지 → 양식 이관

작성일: 2026-09-19
상태: 승인 대기
상위 스펙: `docs/superpowers/specs/2026-09-16-daport-report-tool-design.md` (8.3장, 12장 6단계)
이전 단계: `docs/superpowers/specs/2026-09-18-daport-phase5-ai-editing-design.md`

## 1. 목적

기존 종이 양식의 스캔 이미지를 올리면 레포트 한 장으로 옮긴다. 1단계 스펙 12장이 정한 6단계 완료 기준은 "기존 양식 이관"이다.

AI의 역할은 5단계와 같다. **이미지를 읽고 요소 목록을 내놓는 역할**로 한정하고, 서버가 검증한 것만 캔버스에 제안으로 겹쳐 보인다. 사용자가 적용을 누르기 전까지 모델은 바뀌지 않는다. 적용은 되돌리기 한 단위다. 5단계의 제안·적용·폐기 구조를 그대로 재사용하고 새 상태는 만들지 않는다.

## 2. 원칙과 확정된 결정

| 항목 | 결정 |
|---|---|
| 입력 | 이미지만. PNG·JPEG. PDF는 범위 밖(래스터화 수단이 더 필요하다) |
| 보정 | 서버 전처리 포함. EXIF 회전 → 기울기 보정 → 여백 트림 → 리사이즈 |
| 모델 호출 | 비전 1회. 실패 시 형식 재시도 1회까지, 두 호출이 하나의 제한 시간을 나눠 쓴다 |
| 정확도 | 모델 1회 + 사용자 보정. 제안 오버레이와 원본 대조 배경으로 사람이 고친다 |
| 산출물 | 레포트 페이지 전체(요소 배치), 표 구조, 컴포넌트 후보(이름 붙은 group), `params` 선언, 표마다 정적 데이터셋 하나 |
| 좌표 | 모델은 이미지 기준 0–1000 정규화 정수만 낸다. mm 변환은 서버가 페이지 프리셋으로 한다 |
| 컴포넌트 | 서버·모델은 컴포넌트를 만들지 않는다. 기존 "컴포넌트로 만들기" 대화상자를 사용자가 쓴다 |
| 패키지 | 멀티모달·프롬프트·검증은 `packages/ai`. `sharp` 전처리는 studio 서버 전용 `lib/scan.ts` |
| 비노출 | 프롬프트 원문·모델 원응답·API 키는 클라이언트로 가지 않는다. 이미지와 인식한 글자는 로그에 남기지 않는다 |
| 테스트 | 가짜 클라이언트로 전부 커버. 실제 Gemini 호출은 `GEMINI_IT=1`일 때만. 기본 `pnpm test`는 키 없이 통과 |

`GEMINI_API_KEY`, `GEMINI_MODEL`은 5단계와 공유한다. 이관 전용 환경변수는 `AI_IMPORT_TIMEOUT_MS`(기본 90000) 하나다.

## 3. 패키지 구조 변화

```
packages/ai   + LlmInput.images(멀티모달), Gemini 어댑터의 inlineData 전달
              + buildImportPrompt(prompts/import.ko.ts), IMPORT_RESPONSE_SCHEMA
              + validateImported(정규화 좌표 → mm, params 허용, 스키마 검증)
apps/studio   + lib/scan.ts(sharp 전처리, 서버 전용)
              + api/reports/[id]/ai/import/route.ts
              + 이관 시작 UI(빈 레포트), 원본 대조 배경 토글
```

의존 방향은 그대로다. `ai → core, fast-json-patch, @google/genai`. 새 외부 의존은 `sharp`(studio) 하나다. `sharp`는 네이티브 바이너리라 클라이언트 번들에 들어가면 안 된다. `next.config.ts`의 `serverExternalPackages`에 추가한다.

`packages/ai`는 `sharp`를 의존하지 않는다. 이미지 바이트는 이미 전처리된 상태로 넘어온다.

## 4. 전처리 (studio `lib/scan.ts`)

### 4.1 파이프라인

입력은 바이트 버퍼와 선언된 MIME 타입이다. 출력은 JPEG 바이트, 픽셀 크기, 적용한 보정 내역이다.

1. **EXIF 방향 반영**: `sharp(buf).rotate()`를 인자 없이 불러 EXIF 방향대로 세운다. 휴대폰 사진의 뒤집힘을 먼저 잡는다.
2. **기울기 추정**: 그레이스케일 축소본(긴 변 1000px)을 만든다. -10°에서 +10°까지 0.5° 간격으로 돌려 가며 가로 투영 프로필(행별 어두운 픽셀 수)의 분산을 재고, 분산이 가장 큰 각도를 고른다. 글줄이 수평일 때 분산이 최대가 된다.
3. **회전**: 원본을 그 각도만큼 흰 배경(`background: "#ffffff"`)으로 돌린다. 추정 각도의 절댓값이 0.5° 미만이면 회전을 건너뛴다.
4. **여백 트림**: `trim()`으로 흰 가장자리를 잘라낸다. 트림 결과가 원본 면적의 30% 미만이면 트림을 버리고 회전본을 그대로 쓴다(사진이 종이보다 어두운 배경일 때의 오작동 방지).
5. **리사이즈**: 긴 변 2000px로 줄인다. 이미 작으면 키우지 않는다.
6. **인코딩**: JPEG 품질 80. 결과가 4MB를 넘으면 품질 60으로 한 번 더 인코딩하고, 그래도 넘으면 긴 변 1500px로 줄여 다시 인코딩한다.
7. **메타데이터 제거**: `sharp`의 기본 동작대로 EXIF를 포함한 메타데이터를 출력에 싣지 않는다. 위치 정보가 에셋에 남지 않는다.

### 4.2 입력 한도

| 항목 | 값 | 초과 시 |
|---|---|---|
| 파일 크기 | 20MB | 413 `IMAGE_TOO_LARGE` |
| 픽셀 수 | 5천만 (`limitInputPixels`) | 413 `IMAGE_TOO_LARGE` |
| 형식 | `image/png`, `image/jpeg` | 415 `IMAGE_UNSUPPORTED` |

선언된 MIME 타입을 믿지 않는다. `sharp`가 읽어 낸 실제 포맷이 둘 중 하나가 아니면 415다.

### 4.3 mm 변환 기준

사용자가 고른 페이지 프리셋(기본 A4 210×297mm)이 기준이다. 전처리 결과 이미지의 가로세로 비율이 프리셋 비율과 5% 넘게 다르면 경고를 남기되 변환은 진행한다. 사용자가 다른 프리셋으로 다시 돌릴 수 있다.

정규화 좌표 `n`(0–1000)에서 mm으로:

```
x_mm = (n / 1000) * pageWidth
y_mm = (n / 1000) * pageHeight
```

가로·세로를 각각 페이지 치수로 곱한다. 이미지와 프리셋의 비율이 다르면 이 방식이 종횡을 늘여 맞추는 셈이 되며, 위의 5% 경고가 그 사실을 알린다.

적용한 회전 각도와 트림 영역은 경고 목록에 문장으로 남긴다. 결과가 이상할 때 전처리 탓인지 모델 탓인지 가르는 유일한 단서다.

## 5. 모델 계약

### 5.1 멀티모달 입력

`LlmInput`에 선택 필드를 더한다.

```ts
images?: { mimeType: string; data: string }[];   // data는 base64
```

Gemini 어댑터는 이를 `contents`의 `inlineData` 파트로 싣는다. 이미지가 없으면 5단계와 동일하게 동작한다. 기존 호출부는 바뀌지 않는다.

### 5.2 응답 스키마

Gemini 구조화 출력은 `oneOf`·`$ref`를 쓸 수 없다. 5단계와 같이 요소는 JSON 문자열로 받는다.

```
{
  elements: string[],      // 요소 객체 JSON 문자열. x,y,w,h는 0–1000 정규화 정수
  params: string[],        // 파라미터 선언 JSON 문자열 { name, type } — type은 string·number·date
  datasets: string[],      // 표마다 하나. 정적 데이터셋 JSON 문자열 { name, rows }
  explanation: string,     // 한국어 설명. 컴포넌트 후보 안내를 포함한다
  warnings: string[]       // 읽지 못한 영역 등
}
```

### 5.3 프롬프트 규칙 (`prompts/import.ko.ts`)

- 쓸 수 있는 요소는 `text`, `rect`, `line`, `image`, `table`, `barcode`, `group`이다. `repeater`와 `ref`는 만들지 않는다.
- 좌표는 이미지 기준 0–1000 정수다. mm을 쓰지 않는다.
- 글자는 보이는 대로 옮긴다. 지어내지 않는다. 읽을 수 없으면 그 칸을 건너뛰고 `warnings`에 위치를 적는다.
- 글자 크기는 글상자 높이에서 추정한다. 굵기(`bold`)와 정렬(`align`)만 구분한다.
- 표는 머리글 행과 열 경계를 찾아 `table` 요소 하나로 만든다. 열은 제목과 너비 비율로 적는다. 표 안 글자를 `text` 요소로 흩지 않는다.
- `table`은 행 배열을 주는 `source`가 있어야 스키마를 통과한다. 표마다 정적 데이터셋 하나를 함께 낸다. 이름은 `rows1`, `rows2`처럼 순번을 붙이고, `source`는 그 이름을, 각 열의 `value`는 `{{ row.<열키> }}`를 쓴다. 열키는 머리글에서 뽑은 영문 식별자다. 스캔에서 읽은 본문 행은 최대 20행까지 그 데이터셋의 `rows`에 담는다. 이관 직후 표가 그대로 그려지고, 사용자가 나중에 Oracle 데이터셋으로 갈아끼운다.
- 반복되는 조각(머리글, 서명란, 도장란)은 이름을 붙인 `group`으로 묶고, `explanation`에 컴포넌트 후보라고 적는다.
- 라벨 옆의 빈칸이나 값이 채워진 칸은 `{{ params.이름 }}` 표현식 `text`로 만들고, 그 이름을 `params`에 선언한다. 이름은 영문 식별자로 짓는다.
- 로고나 사진 영역은 빈 `image` 요소로 자리만 잡는다. `src`는 비워 둔다.
- 요소는 최대 120개다. 넘으면 중요도가 낮은 장식선부터 버리고 `warnings`에 적는다.

## 6. 서버 검증 (`validateImported`)

5단계 `validateGenerated`를 확장한다. 순서는 이렇다.

1. 요소 JSON 문자열을 파싱한다. 하나가 깨지면 그 요소만 버리고 경고를 남긴다(5단계 Minor 6과 같은 태도).
2. 정규화 좌표를 mm으로 바꾼다. 트리를 순회해 자식 요소까지 바꾼다. 그룹 자식 좌표는 부모 기준이므로 그룹 박스를 먼저 바꾼 뒤 자식은 그룹 크기에 비례해 바꾼다.
3. 페이지 밖으로 나간 최상위 요소를 페이지 안으로 민다. 조정마다 경고를 남긴다.
4. 요소 id가 겹치면 `<type>-<n>`으로 바꾸고 경고를 남긴다.
5. 표현식을 훑어 `params.<이름>` 참조가 모두 `params` 선언에 있는지 본다. 없는 이름을 쓰면 그 요소의 표현식을 빈 문자열로 바꾸고 경고를 남긴다. `row.` 참조는 `table`의 열 정의 안에서만 허용한다. 표 밖의 `row.`·`record.`·데이터셋 이름 참조는 빈 문자열로 바꾸고 경고를 남긴다.
6. `params` 선언을 레포트 `params`에 합친다. 이름은 영문 식별자여야 하고 `type`은 `string`·`number`·`date`만 받는다. 나머지 필드는 core 기본값을 쓴다. 기존 이름과 겹치면 모델 쪽을 버린다.
7. `datasets` 선언을 검사한다. `type`은 정적만, 이름은 `rows<숫자>` 꼴만, 행은 20개까지, 데이터셋은 표 개수까지만 받는다. 규칙을 벗어나면 그 데이터셋을 버리고, 그것을 `source`로 쓰던 표도 함께 버린 뒤 경고를 남긴다. 표 없이 데이터셋만 오면 버린다.
8. core `parseReport`로 최종 검증한다. 통과하지 못하면 400이다.

이관이 건드리지 않는 것은 `components`, `output`, `sample`, `id`, `version`이다. `datasets`는 위 7번 규칙 안에서만 허용한다. 표가 `source` 없이는 스키마를 통과하지 못하기 때문이고, 스캔한 본문 행이 그대로 샘플이 되어 이관 직후 표가 그려진다.

## 7. 라우트

`POST /api/reports/:id/ai/import`

요청 본문은 JSON이다. 5단계 라우트들과 같은 `readJsonBody` 경로를 써서 content-type 검사(415)를 공유한다.

```
{ report: Report, image: { mimeType: string, dataBase64: string }, preset: { width: number, height: number } }
```

응답은 5단계 생성과 같은 모양이다.

```
{ elements: Element[], params: Param[], datasets: Dataset[], explanation: string, warnings: string[], scan: { assetId: string, angle: number } }
```

`scan.assetId`는 전처리한 이미지를 기존 에셋 저장소(`lib/asset-io.ts`)에 넣은 id다. 클라이언트가 대조 배경으로 쓴다. 원본이 아니라 전처리본을 저장한다. 캔버스에 겹칠 그림과 모델이 본 그림이 같아야 대조가 의미 있다. 에셋 한도는 5MB(`MAX_ASSET_BYTES`)이고 전처리 출력은 4MB 이하라 항상 들어간다. 저장은 라우트가 직접 한다(파일 업로드 폼을 거치지 않는다).

레포트에 요소가 하나라도 있으면 400 `AI_NOT_EMPTY`다. 빈 레포트에서만 시작한다.

## 8. 오류 표

| 상황 | 상태 | 코드 |
|---|---|---|
| 지원하지 않는 형식 | 415 | `IMAGE_UNSUPPORTED` |
| 파일·픽셀 한도 초과 | 413 | `IMAGE_TOO_LARGE` |
| 요소가 있는 레포트 | 400 | `AI_NOT_EMPTY` |
| 검증 실패 | 400 | `AI_INVALID_IMPORT` |
| 키 미설정 | 503 | `AI_NOT_CONFIGURED` |
| 한도 초과 | 429 | `AI_RATE_LIMIT` |
| 시간 초과 | 504 | `AI_TIMEOUT` |
| 모델 형식 오류·기타 | 502 | `AI_BAD_OUTPUT` / `AI_ERROR` |

본문은 사유 문구와 코드만 담는다. 프롬프트 원문, 모델 원응답, 공급자 원문 오류는 싣지 않는다(5단계 I2와 같은 규칙).

시간 제한은 `AI_IMPORT_TIMEOUT_MS`(기본 90초)다. 형식 재시도 1회까지 두 호출이 하나의 마감 시각을 나눠 쓴다. 라우트는 `maxDuration = 120`을 선언한다.

## 9. 스튜디오 화면

- 빈 레포트의 AI 탭에 "양식 이미지로 시작"을 둔다. 5단계 생성 모드 옆자리다.
- 파일 선택 후 페이지 프리셋을 확인하고 보낸다. 기본값은 A4다.
- 결과는 5단계 제안 오버레이로 뜬다. 적용·거절·되돌리기가 모두 같다.
- 전처리본을 캔버스에 흐리게 겹쳐 보는 토글을 단다(기본 꺼짐). 이관에서 빠진 요소를 찾는 데 이 대조가 가장 잘 듣는다. 토글 상태는 제안을 적용한 뒤에도 유지된다.
- 컴포넌트 후보는 group으로 들어온다. 사용자가 그룹을 고르고 기존 "컴포넌트로 만들기"를 누르면 된다. 새 경로를 만들지 않는다.
- 인식한 `params`는 적용 시 함께 들어가고 기존 파라미터 패널에 보인다.

## 10. 테스트

- **전처리**: 테스트가 `sharp`로 합성 이미지를 그려 쓴다. 3° 기울인 줄무늬 이미지의 추정 각도가 1° 안쪽인지, 흰 여백을 두른 이미지가 잘리는지, 4MB 초과분이 재인코딩되는지 본다. 실제 스캔본은 저장소에 넣지 않는다.
- **프롬프트·스키마**: 5단계처럼 문구 단언으로 고정한다. 좌표 규칙과 금지 요소 문장이 빠지지 않는지 본다.
- **검증기**: 좌표 변환(그룹 자식 포함), 페이지 밖 보정, id 충돌, params 허용 목록, `row.` 참조 거부를 덮는다.
- **라우트**: 가짜 클라이언트로 오류 표 전체를 돌린다. 기본 테스트에 키가 필요 없어야 한다.
- **E2E**: 작은 고정 PNG 하나를 저장소에 넣고, `AI_FAKE=1` 가짜 응답으로 업로드부터 적용까지 한 번 통과시킨다.
- **실제 호출**: `GEMINI_IT=1`일 때만 도는 통합 테스트를 둔다. 수동 검증 기록은 `packages/ai/README.md`에 표로 남긴다.

## 11. 완료 기준

1. 실제 양식 스캔 3종을 올려 각각 한 번의 호출로 페이지가 만들어지고, 사람이 고쳐 쓸 만한 수준이다(빠진 요소를 대조 배경으로 찾아 보완 가능).
2. 표가 있는 양식에서 표가 `table` 요소 하나로 인식된다.
3. 라벨·값 구조가 `params` 선언과 표현식으로 들어오고, 표는 정적 데이터셋과 함께 들어와 바로 그려진다.
4. 제안을 적용한 결과가 PDF로 나오고, 되돌리기 한 번으로 빈 레포트로 돌아간다.
5. 기본 `pnpm test`가 키 없이 통과하고, E2E가 가짜 응답으로 통과한다.
